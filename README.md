# SOLITUDE

Top-down exploration aboard a generation ship. Open this repository root as the
Unity project; the required Editor version is recorded in
`ProjectSettings/ProjectVersion.txt`.

For focused source navigation, see [the codebase map](CODEBASE_MAP.md).
For the selected floor-driven room-authoring design, see
[Room Authoring](Docs/Architecture/RoomAuthoring.md).

## Project structure

All first-party imported content belongs under `Assets/_Project`. Vendor packages
such as `Space_Exploration_GUI_Kit` and `TextMesh Pro` retain their own roots and
upstream naming. Do not duplicate assets to satisfy a new folder layout.

| Location | Owns |
| --- | --- |
| `Assets/_Project/Domain` | Unity-independent rules, state, policies, and transactions. |
| `Assets/_Project/Application` | Unity-independent workflows, coordinators, and presentation orchestration. References Domain. |
| `Assets/_Project/Core` | Runtime composition, lifecycle, input hosting, clocks, and persistence adapters. |
| `Assets/_Project/Systems` | Services and reusable runtime presentation used by multiple gameplay features. |
| `Assets/_Project/Features` | Concrete gameplay capabilities and their exclusive scripts, authoring data, prefabs, and UI. |
| `Assets/_Project/UI` | Shared fonts, palettes, panel sprites, themes, and UI settings. |
| `Assets/_Project/Art` | Shared production sprites, tiles, and art direction. `Imported` identifies imported source packs. |
| `Assets/_Project/Scenes` | Shipping entry scenes; `Demos` contains nonshipping demonstration scenes. |
| `Assets/_Project/Settings` | Project-owned render pipeline settings, volume profiles, and scene templates. |
| `Assets/_Project/Editor` | Editor-only tools, migrations, build manifests, and validators. |
| `Assets/_Project/Tests` | Domain, Application, EditMode, and PlayMode tests; disposable fixtures are generated by verification. |
| `Assets/_Project/Verification` | Player verification hooks, compiled only with `SOLITUDE_VERIFICATION`. |
| `Tools/ArtSources` | Art source/intermediate material that does not need Unity import. |
| `Tools/Verification` | Isolated test and player-build verification tooling. |
| `work/Reviews` | Retained screenshots/review evidence outside Unity's imported asset tree. |
| `work/Temporary` | Ignored, disposable exports and archives. |
| `.agents`, `.qrspi` | Agent instructions/skills and disposable QRSPI workflow artifacts. |

`Packages` and `ProjectSettings` retain Unity's required root locations. Generated
`Library`, `Temp`, `Logs`, build output, and local Editor/IDE state are not source
assets.

## Placement rules

- Keep exclusive content with its owner. A ship subsystem screen, its diagram,
  and its prefabs belong with that subsystem feature. A new room specific to
  `Features/World/SolitudeStart` can stay in that feature's `Scenes` directory.
- Put shared runtime services in `Systems`. `Systems/Containers` is shared
  container presentation and transfer UI; `Features/Interactables/Containers`
  contains concrete world lockers. These are different responsibilities.
- Put shared visual primitives in `UI`. Interaction prompts remain in
  `Systems/Interaction/UI` with their system, and reuse the shared UI palette,
  fonts, and theme. Inventory/transfer presentation remains in
  `Systems/Containers`; it is not copied into a second UI hierarchy.
- Put reusable ship sprites in `Art/Sprites`, tiles and palettes in `Art/Tiles`,
  and imported ship source art in `Art/Imported/SpaceShip`. The existing
  `Art/SOLITUDE` family retains its art direction, builders, and approved art.
- Keep reference scenes explicitly named and outside the shipping entry list.
  `Art/SOLITUDE/ReferenceScenes` is for art review. Feature-local scenes do not
  automatically become shipping entry scenes.
- Keep screenshots and archives outside `Assets`. Archived review folders keep
  their original `.meta` sidecars for provenance/restoration; Unity does not
  import them from `work`.
- Create folders only when content exists. Do not commit orphan metadata for
  speculative empty folders.

## Naming and safe moves

Use PascalCase without spaces for new first-party folders, scripts, scenes, and
prefabs. Use descriptive snake_case for production image/animation assets, in
line with the SOLITUDE art pipeline. Keep C# filenames aligned with their types.
Imported vendor names, font family filenames, and established serialized names
are exceptions; do not rename them gratuitously.

Move imported assets through Unity's `AssetDatabase`/Project window, together
with their existing metadata. Never regenerate GUIDs as part of reorganization.
Update string-based paths in tools, tests, manifests, and build settings when
moving scenes or assets. Preserve assembly ownership when moving scripts; editor
scripts outside the central Editor folder use an Editor assembly reference.

The item database lives at
`Assets/_Project/Features/Items/Resources/Database.asset`. Its `Resources` folder
is intentional: existing `Resources.Load("Database")` callers retain the same
resource key. Do not rename it or add bulk art to that folder without reviewing
loading and build inclusion.

## Entry point and verification

The shipping entry is `Assets/_Project/Scenes/Wakeup.unity`. Feature development,
demo, and art reference scenes are not automatically added to the build.

- Metadata: `SOLITUDE > Validation > Validate Unity Metadata` in the Editor.
- Runtime composition and authoring checks: see `Assets/_Project/Editor`.
- Complete isolated verification: see [Tools/Verification/README.md](Tools/Verification/README.md).
- Runtime ownership: see [Core/Composition/README.md](Assets/_Project/Core/Composition/README.md).

Commit assets and their metadata together. Keep `Packages/manifest.json`,
`Packages/packages-lock.json`, and `ProjectSettings` under version control.
Preserve the existing Domain/Application/Runtime/Editor assembly boundaries;
add finer assemblies only when dependency isolation or compile time warrants it.
